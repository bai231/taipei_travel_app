# 餐廳與住宿排程 V1（2026-08-31）

本次是本機程式功能更新，沒有變更 Supabase schema、RLS、資料來源白名單，也沒有新增真實景點／餐廳／飯店資料。測試內的假地點僅供離線驗證，不會寫入資料庫或提供給正式 Picker。

## 操作方式

1. 在安排行程選擇景點、餐廳或住宿後，點卡片上的設定圖示（「時段、停留與資訊來源」）。
2. 餐廳可以選餐別、偏好用餐開始時段、用餐分鐘數；畫面會先填入系統預設並直接用於排程，不滿意時再修改。景點也可覆寫停留分鐘數。
3. 新增住宿後可直接自動排程，不必先開啟設定。系統會自動配置住宿日期，將飯店排在住宿日的最後一站；不滿意時再調整住宿日期、最早抵達時間及住宿停留分鐘數。
4. 既有「指定時間」仍支援 00:00–23:59。固定時間不會因預設餐別而被覆寫；若無法準時抵達或違反營業規定，顯示衝突，而不是偽造準時。
5. 結果時間軸可點項目卡片查看資訊來源及修改設定。短時段項目使用精簡卡片，交通圖示仍可開啟交通詳情。
6. 修改結果頁設定會重新排程，並同步回上一層安排頁；失敗時回復修改前的設定。移除住宿會移除該飯店的整段跨日住宿。

## 餐廳規則

| 餐別 | 預設「用餐開始」時段 | 預估停留 |
| --- | --- | --- |
| 早餐 | 07:00–10:00 | 45 分鐘 |
| 午餐 | 11:00–14:00 | 60 分鐘 |
| 晚餐 | 17:00–20:30 | 90 分鐘 |
| 咖啡／點心 | 不另限餐別時段 | 45 分鐘 |

- 這些是產品預設，不是商家營業時間，也不是訂位資訊。
- 使用者可覆寫時段及停留；停留欄位先顯示系統預設，未修改時仍記為預估，只有主動修改後才記為使用者設定。時段需兩端皆填、開始不晚於結束。時段限制的是開始用餐時間，不是必須吃完的時間。
- 未指定餐別時：有鎖定時間就依該時間建議餐別；否則依當日尚未使用的午餐、晚餐、點心依序提出建議。建議不回寫成使用者已確認餐別。
- 排序同時考慮用餐時段、交通及其他固定時間。偏離用餐偏好、同日多筆相同主餐別屬提醒，保留使用者選擇，不擅自增刪餐廳。
- 跨午夜偏好區間尚未支援；可手動指定凌晨用餐時間。00:00–24:00 的開始時段仍可使用，結束端 24:00 表示本日結束。

## 住宿規則

- 日期使用相對旅程的 `checkInDay`、`checkOutDay` 表示住宿涵蓋範圍，結束日必須晚於開始日；最晚可到旅程結束隔日，該日不會被加入額外旅遊日。
- 單間未設定住宿預設涵蓋整趟旅程；多間未設定住宿會依旅程夜晚依序平均分段。同一晚不可設定兩間住宿。
- 每個住宿夜只建立一個「住宿」事件，固定排在該日所有景點與餐廳之後，作為當日最後一站。
- 隔日不在早上重複建立飯店卡片；第一個實際行程的交通直接以前一晚飯店為起點。
- 更換飯店時，當日從前一晚飯店出發，並以新飯店作為當日最後一站。
- 未提供飯店實際規定時，暫以 15:00 最早抵達、住宿停留 30 分鐘估算；畫面明確標示未知及預設。
- 相同住宿位置的跨日銜接不新增虛構交通查詢。
- 訂房成功、空房、寄放行李、晚到入住、最少睡眠時間等沒有被驗證或保證。本版不做訂房，也不假設能寄放行李。
- 完全未選住宿的夜晚保留原本的末站銜接並提示住宿未設定；只要已加入住宿但尚未調整，系統會先自動補上住宿日期。

## 共同交通與衝突

- 三類項目均須有有效座標，使用同一 TDX 服務、快取、限流／冷卻機制及估算備援。此次沒有新增地理編碼 API 或另外一套付費路線供應者。
- 每日最後一段前往飯店的交通需要實際查詢，可能增加整份行程查詢量。
- 小於等於 8 個待排序活動沿用排列枚舉，加入終點飯店的回程成本，優先可行排序；更多活動使用考慮時間窗的貪婪法。距離估時只用於初排，之後依 TDX 結果順序驗證，不保證全域最佳路線。
- 跨日地理分組不把多天的全部停留量誤當成一天的營業限制；方向以明確起點或第一個選擇的地點作參考，第一個實際活動仍可由排序決定。
- 交通延誤、營業時間不符、抵達飯店過早、活動超過當天皆顯示警告，不悄悄刪除項目或假造班次。
- 前一天超過午夜時，次日不得比上一天最後活動實際結束更早出發；本版不自動把超時活動搬到另一日。
- 軟性偏好（用餐時段、同日重複餐別）顯示於卡片資訊；硬性衝突顯示於全行程警告並使該日 `isValid` 為 false。估算交通不等同已驗證可搭乘。

## 資訊來源與未知值

- **使用者已確認安排**：自己指定的時間／停留／住宿日期；不等同商家確認的訂位訂房。
- **資料庫提供**：可解析的完整數字營業區間；仍未核對每週休假、午休或節日例外。
- **預設或估算**：餐別推定、預設停留、飯店自動住宿日期與最早抵達時間、TDX 失敗後的交通時間。
- **未知**：缺少營業時間、飯店規定、價格、房況與訂位狀態。價格為 0 不標成免費。
- `openingHoursRaw` 保存原始 `opening_hours`／`OpenTime`，不假裝已解析星期或分段時段。只有一端的營業時間及缺省 00:00–24:00 不視為已知；明確 `24/7` 例外。

## 資料與持久化限制

- 依先前查核，`Taiwan_Restaurants`、`Taiwan_Accommodations` 沒有座標欄位。這些資料雖能顯示及依縣市欄位篩選，仍不能加入需要交通的排程。必須先補真實座標；本次沒有自動補座標。
- 飯店邏輯透過具有座標的離線測試資料驗證；正式資料尚未補齊前，不能據此宣稱所有真實飯店已可規劃。
- 新偏好目前保存在本次安排流程的記憶體模型中，重算和返回安排頁會保留；未新增 Supabase 儲存欄位或跨重新啟動的持久化。
- Picker 每個地點勾選一次，飯店可設定一段連住日期；同飯店多段不連續住宿的專用操作介面尚未加入。
