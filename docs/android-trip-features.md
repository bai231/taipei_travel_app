# Android 推薦與行程追蹤

- 分支：`klorius-route-optimizer`。
- 安排行程頁已共用推薦結果、必去景點確認與自動補排服務；補排先顯示確認視窗，再加入待安排項目。
- 結果頁播放圖示為「開始行程」，開始時請求通知及定位權限。停止圖示可停止追蹤。通知拒絕不阻止 GPS 追蹤。
- Android 從可見畫面啟動定位前景服務後，切換其他 App、鎖屏或關閉結果頁仍可在同一 App 程序內守護；按「停止追蹤」才停止。若系統終止程序、使用者強制停止或重新開機，不能保證自動恢復。
- GPS 判斷明顯延誤後只會產生「行程備案」並通知使用者；原行程不會自動變更。使用者須在視窗中選擇「套用備案」，也能選擇「保留原行程」。
- 公車與臺鐵已加入前景即時監測：逐段辨識第一段上車及中途轉乘風險，查詢 TDX ETA／臺鐵即時誤點與營運通阻，並顯示最多三個真實路線備案。已完成路段不會被重排；後續路段全部查詢成功且使用者確認後才套用。
- 保母提出行程備案時，確認視窗會列出受影響的「原行程 Before／建議行程 After」時間、地點與交通方式。若是公車／臺鐵風險，先選路線並計算完整後續行程，再預覽對照；只有第二次按「套用備案」才真正替換原行程。
- 即時監測每 30 秒最多檢查一次，同一風險 15 分鐘內不重複提醒；超過五分鐘的即時資料不作為即時判斷依據。
- 開始行程時保留 main 的首個景點天氣綜覽；定位更新與時間檢查沿用天氣提醒服務。綜覽與 GPS 查詢共用同一實例、快取及跨行程的一小時 CWA 請求節流。天氣達門檻時提供提醒，不會未經確認自動替換行程。

## 本機天氣設定

在不提交的 `config/secrets.json` 保留原有欄位，加入 `CWA_API_KEY`，值為氣象署開放資料授權碼。不要把金鑰放入本文件或提交。

重新建置／啟動（只 hot reload 不會更新編譯參數）：

```powershell
flutter run -d <手機裝置ID> --dart-define-from-file=config/secrets.json
```

驗收請使用當天行程：確認推薦及補排確認視窗、定位授權、目前位置與軌跡、停止追蹤、延誤備案的保留／套用選項、通知允許／拒絕。天氣通知只在達到提醒條件時出現，不是每次開始都會通知。

目前「隨時關心」可在 Android 切換 App、鎖屏、離開結果頁且程序仍存活時運作；不支援使用者強制停止、程序被系統終止或重新開機後自動恢復。常駐定位會耗電，旅程結束應主動停止。

價格欄位解析不屬於本批 Android／保母變更。即時備案會按原本或使用者新選的交通模式逐段重查；目前尚未驗證備案抵達時的景點或餐廳營業時間，這部分由負責營業時間的隊友接續。

## Debug 保母測試控制台

Debug APK 的行程結果頁頂部會顯示「Debug 保母測試工具」入口。正式 Release 建置不顯示此入口。

1. 開啟控制台並啟用「模擬模式」。
2. 關閉控制台，回結果頁按「開始行程」。
3. 再次開啟控制台，先用「跳到行程時段」對齊行程日期，再將時間前進 1／5／15 分鐘、切換行程起點或下一個上車站、選擇模擬班次即時狀態與天氣情境。
4. 按「送出模擬 GPS 更新」觸發一次完整保母檢查。
5. 若在追蹤中切換模擬模式，先停止再重新開始行程，讓定位串流切換到正確資料來源。

模擬模式啟用時，GPS、時鐘、公車／臺鐵即時班次狀態、Google 步行／汽車路線與天氣使用測試資料；**大眾運輸備案則會向真實 TDX MaaS 查詢**，每次產生備案都可能消耗額度。即時班次的「查詢失敗」選項只模擬班次資料失敗，不會阻止真實路線查詢。TDX 查無路線、限流或連線失敗時不回退成假路線，原行程不變。模擬模式不寫入 Supabase；測試風險通知仍會送到 Android 系統並標明「測試」。畫面頂端會顯示橘色模擬標示；關閉 App 後模擬狀態即消失。模擬日期須是 TDX 可查詢的日期，且手機需要網路與有效的 TDX 金鑰。
